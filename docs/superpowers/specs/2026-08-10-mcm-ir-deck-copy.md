## 8 · ★ AI가 하는 일 — 100초 (주제 직결, 최다 배분)

```
H:  AI는 쓰게 하지 않는다. 대신 써준다.
    그리고 흠을 지우지 않는다. 그 자리에 그린다.
```

`B:`

| 단계 | 사용자가 하는 일 | **AI가 하는 일** | 상태 |
|---|---|---|---|
| 기록 | 사진 1장 + 상황 칩 탭 | **문장으로 만든다** — 장소·날짜·제품을 엮어 한 편의 글로 | ✅ 구현 |
| 축적 | 아무것도 안 함 | **Recap 생성** — 흩어진 기록을 하나의 이야기로 | ✅ 구현 |
| **수선** | 부위 탭 + 사진 | **REMADE** — 손상 자리에 어울리는 문양 시안 3안 | ◐ 스키마 준비 |
| 스타일링 | 시대 하나 선택 | **Archive Style** — 내 가방을 MCM 전성기 룩으로 | ✳ 제안 |
| 인사이트 | 아무것도 안 함 | **패턴 도출** — 누가, 어떤 상황에, 어떤 제품을 | → 11번 |

`V:` 두 컷.
① 사진 1장 → AI가 쓴 문장 (실제 생성 결과)
② 긁힌 자리 → 시안 3안 → 완성품

`S:` "기존 서비스는 사용자에게 **입력을 요구**했습니다. 저희는 반대로 갑니다.
사진 한 장, 칩 세 번. 여덟 초입니다. **문장은 AI가 씁니다.**

그리고 수선입니다. 여기서 방향을 뒤집었습니다.
저희는 수선을 되돌리는 일로 보지 않습니다. **그 자리에 그립니다.**
AI가 손상 부위에 어울리는 문양 시안 세 개를 만들고, **실물은 MCM 장인이 만듭니다.**
**AI가 손을 대체하지 않습니다. 시안까지입니다.**

AI를 화려한 기능으로 쓰지 않았습니다.
**기록의 마찰을 없애고, 손상을 서사로 바꾸는 데 썼습니다.**"

> ⚠ 정확히 말할 것
> - ✅ 구현: **AI Story 생성 · AI Recap 생성** (`gpt-4o-mini`, `product_recaps` 캐시)
> - ◐ 스키마 준비: **REMADE** — `repairs.ai_image_url`, `source='ai_custom'` 컬럼 존재, 생성 파이프라인 없음
> - ✳ 제안: **Archive Style** — 미구현. REMADE와 **같은 이미지 생성 경로**를 공유한다
> - **"만들었다"가 아니라 "컬럼까지 준비됐고 다음 단계"**로 말할 것
> - **"AI가 제품 상태를 분석"은 금지.** `compute_care_score()`는 규칙 기반 계산이다
>   (기본 70 + 기록당 3/최대 12 + 수선당 6/최대 12 + 최근 90일 활동 6, 상한 100)
>   **"등록된 기록으로 산출한다"**고 정확히 말하면 오히려 신뢰가 올라간다

## 10 · 데모 — 90초

```
H:  매장에서 산 박스가 서비스의 시작점이다
```

`V:` 순서 고정
1. **박스 QR/NFC 스캔** → 스크롤에 따라 박스가 열린다 *(Challenge 02)*
2. 등록 → 타임라인 첫 줄 자동 생성 (**빈 화면을 한 번도 안 보여준다**)

4. **수선 접수 — 제품 실사 위에서 부위를 직접 탭한다** → 증상 선택

`S:` "박스를 여는 속도는 사용자가 정합니다. 스크롤을 멈추면 애니메이션도 멈춥니다.
등록하면 구매 기록이 자동으로 첫 줄에 찍힙니다. 빈 타임라인은 절대 보여주지 않습니다.
사진 한 장을 올리면 AI가 문장을 씁니다.

그리고 이 화면입니다 — **제품 사진 위에서 부위를 직접 누릅니다.**
글로 '왼쪽 아래 모서리가 까졌어요'라고 쓰는 게 아니라, 그 자리를 누릅니다.
그래서 이 데이터는 자유 서술이 아니라 좌표와 분류로 남고, **그대로 집계됩니다.**"

## 부록 A · Q&A 대비

| 질문 | 답 |
|---|---|
| **"AI가 핵심이 맞나"** | 사용자가 입력을 안 한다는 게 이 문제의 본질이고 AI가 그 마찰을 없앤다. 그리고 REMADE는 AI 없이는 성립하지 않는다 |
| **"AI가 장인을 대체하나"** | **아니다. AI는 시안까지고 실물은 장인이 만든다.** 이 선을 먼저 그을 것 |
| **"Coachtopia랑 뭐가 다르냐"** | Coachtopia는 제품 중심(소재·순환), 우리는 소유자 중심(상황·행동). Coachtopia는 자사 서브브랜드 전용, 우리는 기존 DPP 위에 얹는 레이어 |
| **"Arianee가 하면 되지 않나"** | Arianee는 인프라. 소비자가 두 번째로 열 이유를 만들지 않는다 |
| **"리폼하면 가치 떨어지지 않나"** | 진품성을 증명 못 할 때만 그렇다. **브랜드 공식 + DPP 기록**이면 유일성 증명이 된다 |
| **"MCM 실적이 안 좋은데"** | ⚠ **먼저 꺼내지 말 것.** 물으면: "MCM도 2024년부터 디지털 중심 럭셔리로 전환 중입니다 `[B5]`. e커머스가 이미 글로벌 매출의 30%입니다 `[B6]`. 저희는 그 전환의 실행 도구입니다." **숫자를 먼저 말하지 않는다** |
| **"개인정보는"** | 집계는 **동의한 사용자만**. 5건 미만 그룹 제외(k-익명성). 동의 없이도 개인 기능은 전부 동작. **코드로 보여줄 수 있다** |
| **"시장 규모"** | ⚠ 미확보 `[G5]`. **숫자를 지어내지 말고 "산정 중"이라고 답할 것** |
| **"신사임당 이야기 사실인가"** | **전해지는 일화**라고 정확히 답할 것. 근거는 Dapper Dan `[A10]`이다 |
